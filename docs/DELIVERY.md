# 多端电商系统 · 交付文档

## 1. 交付概述

一套**前后端彻底分离**的多端电商系统：**一个后端 API 服务支撑 PC / H5 / 小程序 / APP 全部前端**，覆盖从登录、购物到支付、售后、运营的完整交易闭环，并实现多商户、B2B/B2C 混合、多语言多货币、实时同步、安全风控等进阶能力。

| 项 | 内容 |
|---|---|
| 后端 | Node.js 22 + Express（模块化单体，可渐进拆分微服务）+ WebSocket |
| 前端 | PC：Vue 3 + Vite + Element Plus（门店端 + 管理后台）；多端：uni-app + Vue 3（H5 / 微信小程序 / APP） |
| 数据库 | MySQL 8（真实接入并全量验证）+ 开发用 JsonStore 双实现 |
| 代码量 | 后端 ~40 模块 / PC 前端 30+ 页面 / 移动端 27+ 页面 |
| 测试 | **集成 169 项 ×2（JsonStore + 真实 MySQL 双库全绿）、单元 18、并发压测 14、订单超时 9 —— 合计 379 项断言全绿** |

## 3. 架构与设计原则落地

### 前后端彻底分离（一套后台支撑所有终端）
```
PC 门店端 ─┐
PC 管理后台 ─┤  REST /api/v1 + WebSocket     ┌──────────────┐
H5 ─────────┼───────────────────────────────► │  统一 API 网关  │──► MySQL 8
微信小程序 ──┤     （JWT 统一认证 + 角色隔离）  │  Express 模块化 │──► 文件存储(dev)
APP ────────┘                                └──────────────┘
```

### 微服务可渐进（模块化单体）
- 路由按 feature 模块组织（auth/product/cart/order/payment/marketing/cms/dashboard/merchant/…），模块间仅通过数据层通信；
- 订单创建/支付回调/秒杀/超时取消均通过 `queue` 抽象解耦（内存实现，可换 Redis/BullMQ）；
- 数据层 `store` 接口双实现（JsonStore / MySqlStore），升级数据层零路由改动。

### 统一数据与实时状态
- 全局唯一数据模型（见 docs/database.md）；购物车/通知/直播/看板等状态经 WebSocket 实时多端同步。

# 2) PC 前端（:5173，门店 http://localhost:5173，后台 http://localhost:5173/admin.html）

# 3) 移动端 H5（:5174）

# 演示账号
admin / admin123      # 管理后台

user / user123        # 买家（含 1280 积分 + 已完成订单）

## 7. 已知边界与后续建议

- 支付为沙箱演示 + 真实回调验签骨架；上线需替换微信/支付宝商户密钥并接入真实统一下单。
- 秒杀并发防护为进程内原子判定；多实例部署需启用 Redis DECR（架构预留）。
- 直播流地址为占位 HLS；虚拟试衣为尺码推荐 + 渲染占位，可接入腾讯云/3D 服务。
- Redis 缓存/队列为内存实现 + 接线文档；接入 Redis 即启用。
- 依赖审计：本机 npm registry 未实现 security audit 端点（NOT_IMPLEMENTED），无法在本地执行 `npm audit`；建议部署侧在官方 registry 环境执行。
